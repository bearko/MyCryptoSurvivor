# プロジェクト憲章 — MyCryptoSurvivor

> 派生プロジェクト初期化時に最初に書き換えるドキュメント。
> このファイルが MyCryptoSurvivor のプロダクト目的を定義する。

## 1. プロジェクトの目的

MyCryptoSurvivor は MCH 経済圏をモチーフにした **「カイロソフト風 + 雪山サバイバル」** のシングルプレイ web ゲーム。
プレイヤーは 10 名の MyCryptoHeroes ヒーローから 1 名を選び、 限られた日数 (= サバイバルゲージ) の中で
資源収集 / クラフト / クエスト / モンスター遭遇を回しながら、 最終的に脱出条件を満たすことを目指す。

> **位置付け**: `mycryptotemplate` 由来の最初の派生作品。 Charter / 開発作法は
> テンプレートをそのまま継承し、 ゲームメカニクスのみを差し替える。

## 2. スコープ (= 何を作るか)

### In Scope (= 作るもの)

- **タイトル画面** — テキストロゴ + Press to Start + 言語トグル (= 画像ロゴは Day 1 では作らない)
- **ヒーロー選択モーダル** — 10 体のプレイアブルヒーローから 1 名を選ぶ Day 1 入口 (= Phase 1 ではプレースホルダタイル 10 個)
- **メインゲームループ** — 日数進行 / 資源 / 体力 / 体温 / 食料 のサバイバルパラメータ (= Phase 2 以降で実装)
- **クラフト / クエスト** — 既存テンプレートの並行スロット accessor パターンを継承 (= Phase 2 以降)
- **i18n** — ja / en (= テンプレートと同じく `data-i18n` 属性ベース)
- **ランキング送信** — 生存日数 / 脱出時刻を GAS 経由で記録 (= Phase 3 以降)

### Out of Scope (= 作らないもの)

- マルチプレイ / オンライン同期
- ガチャ・課金導線
- ブロックチェーン / NFT トランザクション (= ヒーロー画像は CDN 参照のみ)
- 重い 3D / WebGL 演出
- Native アプリ化 (= 静的 web のみ)

## 3. 成功基準

- ユーザーが **タイトル画面 → ヒーロー選択 → ゲーム開始** までを 30 秒以内に到達できる
- モバイル (= 320px 幅) でレイアウトが破綻しない
- ランキング送信エラー率 1% 以下 (= GAS タイムアウト含む)
- 1 プレイの平均所要時間 5〜15 分 (= スキマ時間に回せる)
- ja / en の 2 言語で UI 文字列が 100% カバーされる

## 4. 制約

- **技術**: バニラ JS + 静的 host 限定 (= ビルドステップなし、 npm dependency なし)
- **アセット**: `bearko/MyCryptoSurvivor-assets` リポジトリの raw URL を参照 (= 本リポジトリにバイナリは置かない)
- **多言語**: ja / en の 2 言語デフォルト
- **ターゲット**: PC ブラウザ + モバイル (= iOS Safari / Chrome Android)
- **localStorage prefix**: `mcs.*` で統一 (= 他派生作品と衝突しないこと)

## 5. 主要なペルソナ

- **コアプレイヤー** — MCH 経済圏のファン。 ヒーローの個性 (= スタッツ、 元素属性) を活かした
  ビルド選択を楽しむ。 1 プレイ短く、 何度もリトライしたい。
- **ライト層** — カイロソフト系シムが好きで、 数値とイベントの起伏で遊びたい。 サバイバル系の
  リソース管理は好きだが死にゲーは苦手。 失敗してもすぐ次が始められることを期待。
- **モバイル層** — 通勤途中などで片手プレイ。 縦持ち 320-420px 幅で破綻しない UI が必須。
