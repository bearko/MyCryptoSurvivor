# SPEC-148 — 負けた理由の分析（被ダメの内訳・DPS・前回と自己ベストとの比較・マインちゃんのおすすめ）

- **Status**: Done（下書き #185 → 作者の答え（§6）→ 実装 PR）
- **関連**: SPEC-116（倒れたらスキルツリーへ）・SPEC-136（GUM の内訳）・SPEC-144（数字と用語の色）・SPEC-146（もう一度挑む）・SPEC-147（EASY）

## 1. 作者の依頼（2026-10-21）

負けても「敵の物量に押された」としか分からず、 スキルツリーでどのパネルを取れば打開できるか想像しにくい。 被ダメだけでなく DPS なども見られるようにし、 前回の敗北との比較も見たい。

## 2. 記録するもの（`state.run.stats`。 挑戦のあいだ積む。 純関数は `js/battle/run-stats.js`）

| 項目 | 中身 | どこで積むか |
|---|---|---|
| 被ダメの内訳 | 接触 / 弾（撃つ敵） / ボス（接触・技・弾） / 仕掛け（珠・パンチカード） | `hurt.js` の `hurtPlayer` に `kind`・`name` を足した（接触は `enemies.js`、 弾は `enemy-shots.js`、 仕掛けは `gimmicks.js`。 ボスは `boss` から導く） |
| とどめ | 最後に受けたものの出どころと名前（型があれば「疾走 クリーパー」） | `hurtPlayer` が HP 0 で `recordDown` |
| 与ダメ | 出どころごとの合計 → DPS（= 合計 ÷ 生存秒）。 ボスへの与ダメは別に | `damage.js` の `hitEnemy(idx, dmg, src)`。 武器は `w:<extId>`（弾・周回・レーザー・爆弾・衝撃波に `weaponExtId` を乗せた）、 ほかは `sig`（固有スキル）/ `ll` / `thunder` / `gimmick` |
| 撃破 / 分 | 撃破数 ÷ 生存分（壺・宝箱・木馬は数えない） | `hitEnemy` |
| 回復 | パンケーキ・自然回復・来店・見送りの礼（店とレベルアップ）・不死鳥 | それぞれの場所で `recordHeal`（上限で切れたぶんは数えない） |
| 生存 | 戦闘が進んだ時間（= 止まっているあいだは進まない） | `index.js` の `_step` |

- 下書きにあった「無敵で防いだ回数」は入れていない。 接触は毎フレーム `hurtPlayer` を呼ぶので、 無敵時間の中の回数が「触れていたフレーム数」になってしまい、 数字として意味を持たないため。
- 与ダメは倒した敵の残り HP で切らない（= 過剰分も数える）。 武器どうしの比べ方が素直で、 回ごとの比較も安定するため。
- **仕掛けが敵に与えたダメージは与ダメに入れない。** ステージ 1 のそろばんの珠だけで与ダメの 67% になり、 DPS が自分の火力でなくなっていた（ブラウザで確認）。 仕掛けによる撃破は、 ゲームと同じく撃破数には数える。

- **前回**は同じヒーロー・同じモード（NORMAL / ABSOLUTE / EASY）の前回の敗北（全クリアの画面では前回のクリア）。 **自己ベスト**は長く生き残った挑戦（同じなら撃破数）。 どちらも `localStorage["mcs.runlog.v1"]`（この端末のもの。 共通基盤には送らない）。 初めては「—」。
- ▲▼ は差の向き、 色はよくなったか（被ダメ/分 は少ないほうが緑）。 回復は矢印だけで色は付けない。
- 自己ベストを更新したら見出しの横に「自己ベスト更新！」。
- 色分けは SPEC-144 と同じ系統（数字は金・見出しは水色）。 描くのは `js/battle/analysis-ui.js`。
- EASY は短いステージなので、 NORMAL とは別の鍵で記録する（混ぜると自己ベストが EASY の 1 分で止まるため）。

## 4. マインちゃんのおすすめ（倒れた画面。 木を始めていれば SPEC-116 のひとことの代わりに 1 つ）

| 条件（優先順） | おすすめ（文は `advice.*`） | 節 |
|---|---|---|
| 弾の被ダメ ≥ 45% | 「弾で削られてるね。「厚い皮」（受けるダメージ −3%）か「受け身」（無敵時間）がおすすめ！」 | `vit_armor` / `mov_ghost` |
| 接触 ≥ 60% かつ 撃破/分 < 200 | 「囲まれてるね。「鋭い一撃」や「二連」で火力を上げよう！」 | `atk_dmg` / `atk_bullet` |
| 接触 ≥ 60% かつ 撃破/分 ≥ 200 | 「数に押されてるね。「俊足」か「長い腕」で距離を取ろう！」 | `mov_speed` / `atk_range` |
| ボス ≥ 50% | 「ボスの一撃が重いね。「竜の爪」や「見切り」（ボスの道）を！」 | `bos_dmg` / `bos_tele` |
| 仕掛け ≥ 40% | 「仕掛けに当たってるね。予告が出たら離れよう！」（操作の話なので節は無し） | — |
| それ以外 | 「HP が足りないね。「頑丈なからだ」で底上げしよう！」 | `vit_hp` |

- 同じ文を画面の下の帯（マインちゃん）でも言う。 根をまだ取っていなければ SPEC-116 の入口の案内のまま（= 先に木へ）。 RTA では木が効かないので、 表だけ出しておすすめは出さない。
- 節のボタンを押すと、 その節を選んだ状態でスキルツリーが開く（`openSkillTree({ focus, returnTo, retry: true })`。 閉じると倒れた画面に戻り、 強くしたなら「もう一度挑む」へ）。
- 撃破/分 の境目 200 は、 初めての人の 1 回目（SPEC-146 の自動プレイで 200 前後）を目安にした。 `run-stats.js` の `LOW_KILLS_PER_MIN`。
- ボイスはまだ無い（文が決まったら `advice.*` で録る）。

## 5. 敵の役割（別 SPEC-149 で）

隊列（貫通が効く）・盾持ち（範囲が効く）・重撃（被ダメ減が効く）、 ショップでの次のウェーブの予告は、 敵の作り直しになるので SPEC-149 に分ける。

## 6. 作者の答え（2026-10-21）

1. 表の項目は §2 のままでよい。
2. 比べる相手は **前回の敗北（同じヒーロー）と自己ベストの両方**。
3. **全クリアの画面にも出す**（比較は前回のクリアと自己ベスト）。
